CASE-001

Brute-Force Attack Investigation

LAB SCENARIO

Objective

Identify repeated failed login attempts and determine whether the activity is consistent with password guessing or brute-force behavior.

Investigation Steps

  1. Locate failed authentication events in Windows Security logs.
  2. Review Event ID 4625 and extract relevant fields.
  3. Correlate timestamps, source addresses, usernames, and affected hosts.
  4. Check for successful logons following repeated failures.
  5. Document the evidence and recommend appropriate defensive measures.

Defensive Considerations

Review account lockout policies, investigate unusual source addresses, enforce multi-factor authentication where available, and monitor repeated authentication failures.

Windows Security Logs Wazuh SIEM
CASE-002

Suspicious PowerShell Activity

LAB SCENARIO

Objective

Examine a simulated PowerShell security alert and determine whether the command execution is expected administrative activity or potentially suspicious.

Investigation Steps

  1. Identify the affected Windows endpoint and alert timestamp.
  2. Review available PowerShell logs, including Event ID 4104 when script block logging is enabled.
  3. Examine the process, command-line arguments, user account, and parent process where available.
  4. Correlate the activity with surrounding endpoint and network events.
  5. Record findings and determine whether escalation is warranted.

Defensive Considerations

Enable appropriate PowerShell logging, restrict unnecessary administrative privileges, review endpoint protection alerts, and investigate suspicious process chains.

PowerShell Logs Wazuh & Event Viewer
CASE-003

Indicator of Compromise Analysis

ANALYSIS EXERCISE

Objective

Analyze sample indicators of compromise and understand how threat intelligence can support security investigations.

Investigation Steps

  1. Collect sample IP addresses, domains, URLs, or file hashes from a controlled exercise.
  2. Identify the indicator type and validate its format.
  3. Review available threat intelligence information from reputable sources.
  4. Correlate indicators with relevant lab logs or network traffic.
  5. Document evidence, confidence, limitations, and recommended actions.

Defensive Considerations

Validate indicators using multiple sources, consider the context and age of intelligence, and avoid blocking indicators solely on an unverified match.
